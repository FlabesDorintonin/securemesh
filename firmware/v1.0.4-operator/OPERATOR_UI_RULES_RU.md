# SecureMesh v1.0.4 — правила операторского интерфейса

Главный принцип: оператор видит **состояние и действие**, инженер — техническую причину.

В обычных экранах и на OLED не показывать внутренние термины маршрутизации, BLE-транспорта и метрики протокола (`G2`, `manifest`, `PDR`, `RTT`, `ACK`, `opcode`, `payload`, `RSSI/SNR` и подобные). Они остаются в Serial, API, тестах и инженерных отчётах.

Операторские эквиваленты:

- RSSI/SNR/PDR → `ОТЛИЧНО / ХОРОШО / НЕСТАБИЛЬНО / ПЛОХО / НЕТ СВЯЗИ`;
- trend → `УСИЛИВАЕТСЯ / СТАБИЛЬНО / ОСЛАБЕВАЕТ`;
- Primary → `ОСНОВНОЙ ПУТЬ`;
- exact G2 / backup → `ЗАПАСНОЙ ПУТЬ`;
- manifest → `СПИСОК УЗЛОВ`;
- crypto/auth → `ЗАЩИТА`;
- BLE session → `СВЯЗЬ С ТЕЛЕФОНОМ`;
- queue overflow → `ПЕРЕДАЧА ПЕРЕГРУЖЕНА`;
- diagnostics → `ПРОВЕРКА` или `ПРОВЕРКА ИСПРАВНОСТИ`.

В операторском OLED-меню показываются только реально работающие функции. Roadmap/Planned-функции не должны появляться до реализации.

После изменения UI запускать `python tests/operator_vocabulary_check.py`. Это release-gate, а не рекомендация.
