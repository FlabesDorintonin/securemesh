# SecureMesh v1.0.4 Operator

Финальная операторская полировка стабильной Foundation-базы.

Связка релиза:

- firmware: `SecureMesh_v1_0_4_OPERATOR.ino`;
- Commander: `LabPanel/`;
- протокол маршрутизации: **VANGUARD**;
- BLE application protocol: v2;
- BLE fragment transport: v1.

## Что изменилось в v1.0.4

Главная цель — разделить интерфейс оператора и инженерные внутренности системы.

Оператор больше не видит RSSI/SNR/PDR/RTT/G2/manifest/opcode/payload/ACK/heap и другие внутренние термины. Вместо них используются понятные состояния:

- `ОТЛИЧНО / ХОРОШО / НЕСТАБИЛЬНО / ПЛОХО / НЕТ СВЯЗИ`;
- `УСИЛИВАЕТСЯ / СТАБИЛЬНО / ОСЛАБЕВАЕТ`;
- `ОСНОВНОЙ ПУТЬ / ЗАПАСНОЙ ПУТЬ`;
- `ГОТОВ / НУЖНО ВНИМАНИЕ / ОШИБКА`;
- `СВЯЗЬ С ТЕЛЕФОНОМ / ЗАЩИТА / ПЕРЕДАЧА`.

На OLED скрыты все roadmap-функции, которые ещё не реализованы. Меню показывает только то, чем можно пользоваться сейчас.

Инженерные термины не удалены из архитектуры: они остаются в Serial, API, исходном коде, тестах и инженерных отчётах.

## Командирское приложение

Windows: распаковать релиз и запустить `LabPanel/START_COMMANDER.bat`.

Основные экраны:

- Сеть;
- Схема сети;
- Пути связи;
- Проверка резерва;
- Проверка связи;
- Учебная схема;
- Радар устройств;
- Журнал.

Карточки узлов можно переименовывать и закреплять. Link Quality и тренд сигнала отображаются человеческим языком.

## Release gates

После изменения пользовательских строк обязательно запускать:

`python tests/operator_vocabulary_check.py`

Правила интерфейса описаны в `OPERATOR_UI_RULES_RU.md`.

## Граница проверки

VANGUARD native regression и Commander проверяются в этой среде. Полная Arduino-компиляция `.ino` под ESP32-S3 требует локального Arduino/PlatformIO toolchain с конкретными версиями ESP32 core, RadioLib и NimBLE-Arduino.
